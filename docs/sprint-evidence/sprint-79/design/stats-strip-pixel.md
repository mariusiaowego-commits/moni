# stats-strip UIUX 建议

基线：`docs/sprint-evidence/sprint-79/design/prototype-v2.html:63-68`（样式）、`:228-233`（结构）。
范围：只出建议，不改仓库。

现状病灶：三层结构（28px 数字 / 12px 标签 / 12px 第三行）＋ 一卡两口径（`137 高价值` 与 `中 199 · 低 96` 同卡）＋ 一个数字位放两个值（`429 / 3`）＋ 重复（`30+` 在单位与第三行各出现一次）。

---

## 1. 数字卡可读性规则

| 元素 | 规格 | 说明 |
|---|---|---|
| 数字 | `--font-28` 28px / 600 / line-height 1.1 / letter-spacing -0.02em / tabular-nums | 卡内唯一视觉焦点 |
| 标签 | `--font-13` 13px / 400 / line-height 1.4 / `--muted-fg` | 与数字差 2.15 倍，构成两级 |
| 数字→标签间距 | 4px（`--space-1`） | 同一组，不留 8px |
| 卡内 padding | 14px 20px（1440）· 12px 16px（1024） | 卡高由内容决定，约 81–84px |
| 字号档位 | 只用 28 与 13 两档 | 不出现 12/14/16 中间档 |

**为什么删第三行**：
1. 第三行必然引入第二口径（`137` 与 `中199·低96` 不是同一件事），一卡两义，扫读要判断两次。
2. 眼睛落点从 2 个变 3 个，4 张卡共 12 个落点，30 秒扫读目标被稀释。
3. 卡高从 ~81px 涨到 ~99px，4 卡吃掉 99px 首屏，列表首屏少一行。
4. 第三行内容（分布、来源案例）属详情/筛选行职责，不是库级概览。
5. 若确实要表达分布：用一条 4px 高的三段细条贴在卡底（无文字），或直接搬进筛选行的价值维度计数；不要文字行。

## 2. 1440×900 与 1024×768 排布

| | 1440×900 | 1024×768 |
|---|---|---|
| 列数 | 4 列 `repeat(4,1fr)` | 4 列 `repeat(4,1fr)`（每列约 230px） |
| gap | 12px（`--space-3`） | 8px（`--space-2`） |
| 卡高 | 84px（min-height） | 76px（min-height） |
| padding | 14px 20px | 12px 16px |
| 横向滚动 | 不需要 | **不需要** |
| 换行 | 不换行 | **不换行** |

- 1024 保持 4 列：单个数字 ≤4 字符（`432` / `137` / `30+` / `8`），230px 列宽绰绰有余；换行会把 4 件事拆成 2×2，扫读路径从「一条横线」变「两行折返」，更慢。
- 仅当列宽 <180px（视口 <800px）才降 2×2；这是手机档，不在本次两档内。
- 数字卡不是导航：**不加 hover 抬升、不加阴影**，与 `.case-card` 的 hover 语言区分开。
- 卡与下方 `.facet` 同圆角同边框，形成一条水平节奏；stats-strip 与 facets 之间留 24px（`--space-6`）。

## 3. 长数字处理

| 问题 | 规则 |
|---|---|
| 对齐 | 全部 `font-variant-numeric:tabular-nums`（已具备），`432/137/30+` 纵向等宽 |
| 千分位 | ≥10000 才加（`1,234`）；`432`/`137`/`30+` 不加。用 `Intl.NumberFormat('zh-CN')` |
| 换行 | **禁止换行**：`white-space:nowrap`；数字与单位同行 |
| 超宽兜底 | 优先降档 28→22px，其次缩列距；不换行、不截断 |
| 单位 | 13px，`align-items:baseline` 与数字基线对齐；单位不换行 |
| 一个数字位两个值 | 禁止（`429 / 3` 拆开）：改成单卡 `429` + 标签 `AI 应用`，或直接删掉这张 |
| `30+` 的 `+` | 跟随数字 28px，不缩进单位 |

## 4. 视觉细节（全部走 prototype-v2 token）

| 项 | 值 |
|---|---|
| 底色 | `--card` |
| 边框 | 1px `--border`（杏子灰） |
| 圆角 | `--radius-lg` 12px |
| 阴影 | 无（列表区不用 `--shadow`） |
| 分隔 | 只用 gap，不加竖线；卡内不加分隔线 |
| 数字色 | `--card-fg` |
| 标签色 | `--muted-fg` |
| 强调 | 不用 `--accent` 给数字（accent 留给类型 chip）；要强调只把标签字重提到 500 |
| 等宽 | 4 卡等宽，不做「主卡放大」 |

## 5. 只保留 4 个数字时的建议

**案例数 432 / 高价值数 137 / 企业数 / 场景数**

| 保留 | 理由 |
|---|---|
| 案例数 | 唯一分母，说明盘子大小 |
| 高价值数 | 决策相关：137 条值得抄，是用户真正要的优先级 |
| 企业数 | 覆盖面：多少家公司在做，比行业数更贴「找同类」 |
| 场景数 | 可迁移维度（10 个场景），比类型数（8 类内部 taxonomy）更贴业务 |

**去掉**：
- 类型数：8 类是内部分类，用户不背，且与「AI 应用」chip 重复。
- 行业数：与企业数高度共线，且一级/二级口径歧义。
- 最高频触点：单案例事实（微信小微 30+），属列表卡/详情，不是库级统计。

若只能 3 个：案例数 / 高价值数 / 企业数。
前置依赖：企业数、场景数需 `GET /api/cases/facets` 给 distinct 计数；未就绪前用 facet 选项数近似，并标注口径。

## 三行摘要

1. 数字 28px/600/1.1 + 标签 13px/400，间距 4px，只留两级字号；删第三行（它带来第二口径、第三个落点、多 18px 卡高）。
2. 1440 与 1024 都 4 列不换行不滚动（gap 12/8，卡高 84/76），列宽 <180px 才降 2×2。
3. 保留案例数 / 高价值数 / 企业数 / 场景数；数字 tabular-nums、≥10000 才千分位、禁止换行，卡用 `--card`+`--border`+12px 圆角、无阴影。
