# 案例库顶部 Stats-Strip 重设计方案（agy）

基线：`prototype-v2.html` token 系统（`--card` / `--border` / `--foreground` / `--muted-fg` / `tabular-nums`）。
原则：**一卡一事、严格两级字号（数字 + 标签 ≤4 字）、无第三行说明。**

---

## 1. 三个候选方案

### 方案 A：4 张极简单指标卡（每卡严格 2 行）

```
[ 432 ]        [ 137 ]        [ 116 ]        [ 10 ]
[ 案例 ]       [ 高价值 ]     [ 覆盖企业 ]   [ 业务场景 ]
```

- **结构**：2 行。第 1 行＝数值（`tabular-nums`）；第 2 行＝指标标签（≤4 字）。**删除 `.d` 第三行容器**。
- **文案**：`432 / 案例`、`137 / 高价值`、`116 / 覆盖企业`、`10 / 业务场景`。
- **优点**：沿用现有 `.stats-strip` 4 栏网格，信息扫描极快；从 DOM 结构上锁死「一卡一数」，不可能塞进第二口径。
- **缺点**：占纵向高度约 76px（比紧凑条多 ~24px）。

### 方案 B：1 条紧凑数字带（单行水平 Strip）

```
| 432 案例  |  137 高价值  |  116 企业  |  5 行业  |  10 场景 |
```

- **结构**：整条为 1 张 `.card` 容器，内部 5 等分（1px `--border` 竖线分隔），每格内数字与标签同行或紧凑两行。
- **文案**：`432 案例`、`137 高价值`、`116 企业`、`5 行业`、`10 场景`。
- **优点**：高度压到 48–52px，把首屏空间最大限度留给筛选行和案例卡片；5 个全局维度一次放全。
- **缺点**：1024 下 5 格横向偏紧（每格仅 ~190px），数字不能太大，视觉锚点弱于独立卡片；若折行会破坏竖线分隔。

### 方案 C：2+2 语义分组卡（量质组 + 覆盖组）

```
┌─────────────────────────┐   ┌─────────────────────────┐
│  432 案例  │  137 高价值 │   │  116 企业  │  10 场景   │
└─────────────────────────┘   └─────────────────────────┘
```

- **结构**：外层 2 个分组容器（左「规模与价值」，右「覆盖维度」），每组内 2 个指标（各 2 行：数字 + 标签）。
- **文案**：左组 `432 / 案例` + `137 / 高价值`；右组 `116 / 覆盖企业` + `10 / 业务场景`。
- **优点**：语义分组明确，1024 下天然保持 2+2 对称。
- **缺点**：多出一层分组框线与内外两套间距，比方案 A 视觉噪音更多。

---

## 2. 推荐方案与防退化机制

**明确推荐：方案 A（4 张极简单指标卡）。**

**为什么不会退化成「高/中/低两种口径同卡」：**
1. **DOM 物理锁死**：组件只保留 `.stat-num`（数字）和 `.stat-label`（≤4 字标签）两个节点，**彻底移除第三行 `.d` 副文案节点**——开发和产品想加「中 199 · 低 96」也没有容器可放。
2. **职责剥离到筛选面板**：「高 137 / 中 199 / 低 96」的三档分布属于交互筛选态，交给下方「价值」筛选胶囊展开后的面板选项计数（`高 137` / `中 199` / `低 96`）去呈现，顶部 KPI 卡只保留核心北极星「`137` / `高价值`」。
3. **全局同口径**：4 张卡全部描述**整个案例库**的全局截面（总量、高价值量、企业覆盖、场景覆盖），不混入单条案例或比例。

## 3. 1440 与 1024 排布规范

只允许**两级字号层级**（数字 + 标签），全部走现有 token：

| 断点 | 列数 | 卡高 | 内边距 / 间距 | 层级 1：数字 | 层级 2：标签（≤4 字） |
|---|---|---|---|---|---|
| **1440×900** | 4 列均分（`repeat(4, 1fr)`） | ~76px（自适应，不写死） | `padding: 16px 20px`；`gap: 12px` | `28px`（`--font-28`），`font-weight: 600`，`tabular-nums`，`line-height: 1.1`，色 `--foreground` | `12px`（`--font-12`），`font-weight: 500`，`margin-top: 6px`，色 `--muted-fg` |
| **1024×768** | 4 列均分（`repeat(4, 1fr)`，单卡宽 ~230px，2 行完全够放；仅 `<720px` 切 2×2） | ~68px | `padding: 12px 16px`；`gap: 10px` | `22px`（`--font-22`），同上 | `12px`（`--font-12`），`margin-top: 4px`，色 `--muted-fg` |

*(注：因为每卡只有「一个数字 + ≤4 字标签」，1024px 下 4 列每卡仍有 ~230px 宽，**无需像旧 3 行卡那样掉成 2×2**，省出整整一行纵向空间给首屏列表。)*

## 4. 空态与异常态

| 状态 | 数字区显示 | 标签区显示 | 视觉处理 |
|---|---|---|---|
| **加载中** | `—`（em-dash） | 保持原标签（`案例` / `高价值` / `覆盖企业` / `业务场景`） | 数字色转 `--muted-fg`，`aria-busy="true"`，不做骨架屏闪烁。 |
| **数字缺失 / `null`** | `—` | 保持原标签 | 同上，禁止显示 `NaN` / `undefined` / 空白，也不编造 `0`。 |
| **全库为 0（冷启动空库）** | `0` | 保持原标签 | 正常显示 `0`（不隐藏卡片），下方列表区出空态提示。 |
| **stats 接口报错** | `—` | 保持原标签 | 卡片不崩溃、不弹窗阻塞，由列表区统一提示加载失败。 |

## 5. 现有卡片删改清单与理由

| 原卡片 | 处置 | 理由 |
|---|---|---|
| 卡 1：`432 案例` + `高价值 137` | **保留主数字，删掉第 3 行** | `137` 已在卡 2 独立展示，放卡 1 属重复表达，且同一张卡混了总库与高价值两种口径。 |
| 卡 2：`429 / 3` + `AI 应用 / 产品创新` + `类型分布` | **删除，换成 `116` / `覆盖企业`** | ① `429 / 3` 是旧版二分归类失真的产物；② 斜杠拼两数违反「一卡一数」；③ 企业聚合是 2.0 核心能力，`116 覆盖企业` 价值远高于 `429/3`。 |
| 卡 3：`137 高价值` + `中 199 · 低 96` | **保留主数字，删掉第 3 行** | 同卡混入高/中/低两套口径；中/低档计数移入下方「价值」筛选面板，顶部只看高价值标杆数。 |
| 卡 4：`30+ 最高频触点` + `微信小微 · 30+` | **删除，换成 `10` / `业务场景`** | ① `30+` 是单条案例（微信小微）的局部指标，不能与全局统计并列；② 标题与副行重复写 `30+`。换成 `10 业务场景`（或 `5 覆盖行业`）保持全局口径一致。 |

## 6. 三行摘要

1. **推荐方案 A（4 张极简单指标卡）**：`432 案例` / `137 高价值` / `116 覆盖企业` / `10 业务场景`，彻底删除第 3 行副文案，从 DOM 结构上杜绝一卡多口径。
2. **删旧换新**：砍掉失真且双数的 `429 / 3 类型分布` 与局部口径的 `30+ 最高频触点`，分别替换为全局口径的 `116 覆盖企业` 与 `10 业务场景`；高/中/低明细下沉到筛选面板。
3. **1440 与 1024 均保持 4 列单行**：仅两级字号（28/22px 数字 + 12px 标签），加载中与缺失统一显示 `—` 不闪烁、不崩溃。
