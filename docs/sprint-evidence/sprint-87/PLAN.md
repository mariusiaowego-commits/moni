# Sprint 87 · 分享页 v2 与用户上下文呈现

## 背景

用户对分享页提了 5 条诉求（PR #352），随后追加两轮：队列列宽/操作列被裁（PR #362）、
上下文段落没渲染且太长看不出重点（PR #367）、上下文卡片不标所属文章且详情太长（PR #370）。
四次改动同属「分享页」一条线，合并为一个 sprint 记录。

## 需求

1. 每个产出物在列表里展示包含的「增强特性」；PNG 还要展示「生图方式」。
2. 简报需要输入标题时，默认 `同业简报-YYMMDD-<格式>-NN`，同格式当天自增。
3. 上下文在产出物里要能读：分段渲染 + 一段 TLDR，长文默认折叠。
4. 分享页 `share-card` 对带「AI 对话」上下文的文章要有标记。
5. `share-picker-toolbar` 右侧按钮 UI 统一。
6. 队列「产出产物」列改名「简报链接」、收窄到 280px，操作列不再被裁。
7. 落地页上下文卡标注所属文章；详情按分节渲染（编号条目双列瀑布流，整段内容保持整段）。

## 方案

- 入队时把 `features` / `generation_approach` / `options` / `title` 快照写进 `share_tasks.extra`；
  历史行无 extra 也无队列文件时标 `config_unknown`，不假装知道生成方式。
- `GET /api/share/next-title?format=<id>` 预览默认标题，序号按「格式 + 本地日」取最大值 +1；
  仅作标签，不占用唯一键。
- 上下文**不进 LLM**（红线）：TLDR 走抽取式（正文第一段「结论：…」剥前缀取第一句，≤180 字），
  详情用 mistune（`escape=True`）渲染后折叠；未装 mistune 退回转义纯文本。
- 详情结构化：按「一、xxx」分节，编号条目（关键事实 / 案例与实验）铺 `columns: 280px 2`
  双列瀑布流并拆「主张 + 证明」；无出处 / 未知保持整段；解析不出分节退回原 markdown。
- 两条渲染路径共用 `context_pack.detail_css`：独立 HTML 注入在 section 内自带 `<style>`，
  简报内嵌复用 `brief_html.py` 的 CSS。

## 不在本次范围

- 不改 `article_contexts` schema，不做上下文生成的模型化摘要。
- 不重生成历史产出物（只对用户点名的那一份做幂等重注入，留备份）。
