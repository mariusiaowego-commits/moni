# Sprint 81 · 案例库 UI V3（/cases）PRD

## 目标

把已拍板的 V2 设计（`docs/sprint-evidence/sprint-79/design/prototype-v2.html`、
`filter-mock.html`）落到生产 `/cases`：概览带、筛选、卡片、沉浸详情四块，
并保证换 theme 只换 token。

## 用户故事

1. 进入 `/cases` 第一眼看到「盘子多大 + 什么最多」：4 格 KPI + 类型/行业/场景 Top4 分布。
2. 用搜索 + 6 个维度（企业/行业/场景/类型/价值/时间）筛到目标案例，条件可回退、可分享 URL。
3. 卡片 30 秒能判断「谁做了什么、值不值得看」，不再出现药丸墙。
4. 点卡片进入沉浸详情：结论、指标、依据、原文证据（区分引用/转述）、基本信息、标签、分享。
5. 亮/暗主题切换时，案例页不出现硬编码色。

## 范围

- 后端：`/api/cases` 增加 6 维筛选 + q；`/api/cases/facets` 新增；`/api/cases/stats` 补口径；
  `/api/cases/{id}` 补行业/场景/类目/相关案例。
- 前端：`index.html` cases 区块、`cases.js`、`main.css` 新增 `cv-*` 样式。
- 分享：详情内「生成案例简报」入队后跳到分享页队列。

## 非目标

- 不接 `case_insights` 的 LLM「做法/风险」段落（表未回填，不伪造）。
- 不做案例卡片 PNG 导出、不做跨文章语义搜索。
- 不改 `case_brief.py` 排版（已在第二轮统一）。

## 验收

- 432 案例 / 137 高价值 / 305 机构 / 10 场景四个数字与 SQL 复算一致。
- 6 维筛选与搜索组合后列表、命中数、URL 三者一致；清空可回到全量。
- 1440 / 1024 无横向滚动；1024 分布标签不截断；亮/暗对比度达 AA。
- 新增后端测试通过；全量 pytest 通过；浏览器控制台无报错。
