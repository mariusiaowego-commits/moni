# PRD: 一键简报 (v1.0.10)

> moni · 2026-07-28 · Draft  
> 作者: agent + 用户诉求  
> 关联 Plan / Spec 同目录

## Problem Statement

作为 moni 的日常使用者，我已经用 Pin 收集了「今天值得跟进」的同业文章，但要把它们变成一份可分享/可决策的简报，仍需在分享页完成大量手动步骤：逐篇勾选、反复勾内容选项、BestBlogs 增强、加入队列、再手动启动 worker。操作多、易漏、状态心智分裂。

结果是：Pin 有了，价值链断在「理解 → 产出」——摘要/事实核查覆盖率低，分享很少真正跑通。

## Solution

提供 **「一键简报」主路径**：

1. 用户在文章流 pin 关心的文章（已有能力）
2. 打开分享页 → 选输出格式 → 点 **「用当前 Pin 生成简报」**
3. 系统自动：拉取全部当前 Pin → 按需生成/复用摘要 → 事实核查 → 质量/业务价值评判 → 按格式渲染 artifact
4. 全程在分享页状态区可见进度；离开后回来仍可看

旧的「精细勾选 + 选项」路径保留为「自定义分享」，默认折叠。

## User Stories

1. As a moni 用户, I want 用当前全部 Pin 一键生成简报, so that 不必逐篇勾选
2. As a moni 用户, I want 只选择输出格式（markdown/html/pdf/png 等）, so that 决策点只剩一个
3. As a moni 用户, I want 简报自动含 AI 摘要, so that 不必先手动跑摘要
4. As a moni 用户, I want 简报自动含事实核查, so that 转述给同事时心里有底
5. As a moni 用户, I want 每篇有评分（质量/可信度类）, so that 能快速排序注意力
6. As a moni 用户, I want 每篇有「对自身业务价值」评判, so that 同业信息能落到工作优先级
7. As a moni 用户, I want 一点按钮后自动开始处理, so that 不必再点「立即处理队列」
8. As a moni 用户, I want 随时看到生成到哪一步, so that 长任务不焦虑、可离开再回
9. As a moni 用户, I want 失败时看到可读原因并可重试, so that 不依赖翻 worker.log
10. As a moni 用户, I want 完成后直接打开产物, so that 链路闭环
11. As a power user, I want 仍能自定义文章集合与 BB/provider 选项, so that 特殊场景不被锁死
12. As a moni 用户, I want 已生成过的摘要/核查/业务价值被复用, so that 同一批 pin 再出另一种格式更快
13. As a moni 用户, I want 默认选项合理（无需理解 BB 额度/provider）, so that 零配置可用
14. As a moni 用户, I want 看到本次将处理几篇文章与预估耗时, so that 有预期（轻量，不阻断）
15. As a moni 用户, I want pin 在生成后默认保留, so that 可改格式再生成（可选后续：完成后建议 unpin）

## Implementation Decisions

### 产品
- **主 CTA**：`用当前 Pin 生成简报 (N)`；N=当前 pin 总数；N=0 时 disabled + 引导去 pin
- **默认 enrichment 全开**：摘要 ON、事实核查 ON、业务价值 ON；BB 增强默认 OFF（避免额度惊吓）
- **评分**：优先复用 `bb_score`（若有）；否则 LLM 给 `quality_score` 或写入业务价值旁的质量分（见 Spec）
- **create → auto launch worker**：`POST /api/share/brief` 内部 `write_manifest` + `launch_worker()`
- **状态**：复用 `share_tasks.progress_*`；扩展 stage 文案；前端全局 poll（进分享页即 poll）
- **旧路径**：保留 `加入队列` + 选项，收入「自定义分享」`<details>`

### 模块
1. **Brief API** — 新 endpoint，封装 pin 全量 + opinionated payload
2. **Enrichment pipeline** — 在 worker/summary_gen 中：summary → fact_check → business_value（落库可复用）
3. **Share UI** — 一键主路径 + 状态面板强化
4. **DB migration** — 业务价值字段（article 级缓存）

### 关键交互
- 点击主 CTA →（可选轻量 confirm：N 篇 + 格式 + 预估分钟）→ 立即创建并启动
- 状态区固定展示「当前简报」卡片：阶段步进 + % + 最近 message
- 历史队列表仍在，但当前 task 高亮

## Testing Decisions

- 测外部行为：API 契约、默认 payload、auto-launch 调用次数、空 pin、progress 字段
- 不测 hermes 真实输出（mock subprocess / 注入 fake enrichment）
- 对标现有 `tests/test_share*.py`、`tests/test_pins*.py` 风格

## Out of Scope

- 定时每日简报 / 邮件推送
- 多用户 / 权限
- 分享产物 design token 大改
- 文件队列废除
- 语义去重 / 事件聚类

## Further Notes

- 审计结论对齐：P1「每日简报 + 自动摘要」的最小可交付是 **手动触发的一键简报**，先把链路跑顺再自动化日程。
- 「业务价值」需固定 moni 场景 persona（默认：银行/支付/数字化同业情报读者），避免空泛打分。

## 评审锁定（2026-07-28）

三方评审均为 **Approve with changes**。产品补强：

1. **简报 ≠ 逐篇 dump**：markdown 产物顶部强制 **Executive rollup**（优先关注 3–5 条，按业务价值分排序）+ 逐篇区块（摘要 / 事实核查 / 评分 / 业务价值）。
2. **对外只暴露一种「质量/注意力」分**：有 `bb_score` 用它；否则 quality/LLM 分；**业务价值分永远单独**。
3. **一键 = 真·一次点击**：无 estimate modal；无「立即处理」；title 自动生成。
4. **随时看状态** = sticky「当前简报」卡片（阶段中文 + % + message + 打开产物/重试），不是只靠队列表格。

开放决策已全部锁定，见 Plan「决策锁定」表。
