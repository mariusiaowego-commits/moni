## 关键决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | `article_pins` 独立表 (FK CASCADE) | 数据隔离, 删 article 自动清 pin, 未来易扩展 |
| 2 | Pin tab 在文章查阅下, 不放顶层 nav | 文章查阅本身就是阅读/管理入口, pin 跟列表场景近 |
| 3 | Share page 加 chip 切换, 默认 Pin 模式 | 你决策 3 |
| 4 | 5s 倒计时条 + 内存撤销, 刷新失效 | 你决策 4, 不弹 modal, 轻量 |
| 5 | 无 pin 数量限制 | 你决策 5, 软提示 (pin > 500 时 share page 顶部 "建议先按 tag 筛选") |
| 6 | Pin icon: nullframe 风格 SVG, 不用 emoji | 你 push 1, 几何栅格化, 用 moni 强调色 (紫藤萝) |
| 7 | DELETE /api/articles/{id}/pin 也支持 (跟 ?on=false 等价) | RESTful 直觉, 测试用例好写 |
| 8 | 列表行 Pin 按钮: 紧贴"查看"前 | 不破坏现有列布局 |
| 9 | Pin toggle 走乐观更新 | 避免 5s 倒计时期间用户感觉延迟 |

## 风险 + 兜底

| 风险 | 兜底 |
|------|------|
| CASCADE 在 SQLite 默认不开启 | migration 显式 `PRAGMA foreign_keys = ON` (已有) |
| 大 pin 列表 (500+) share page 卡 | 后端分页 + 软提示 |
| 5s 倒计时期间用户关浏览器 | 5s 内的 unpin 不持久化, 下次进页面还是 pin 状态 (温和) |
| 用户 5s 内二次 unpin | 第二个 batch 覆盖第一个的 ids (additive, 无副作用) |
| 多 tab 同步 | 不强求, session 内一个 tab 足够, 切 tab 重新拉数据 |
