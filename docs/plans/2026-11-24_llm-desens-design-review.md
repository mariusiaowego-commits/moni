## 2. 合并版留下了什么，以及「好在哪」

### 2.1 来自方案 A（agy）的三处硬料

1. **插入点的否决理由被补全（合并版 §2）**
   方案 B 只列了 3 个候选；A 补上了「只改 `call_llm()` 覆盖约 55%，漏掉 reader / share / stream /
   fact_check_plus 四条」和「本地 sidecar 违反 `moni/llm/gateway.py:7` 只读红线」两条。
   **为什么好**：决赛现场点阅读器或一键简报就穿帮 —— 覆盖率论证必须先堵死「只改一个函数」的省事方案。

2. **magpie 源码索引（合并版 §15，15 条 `path:line`）**
   不是转述官方文档，而是逐条落到 `internal/redact/redact.go:828` `tag()`、`:1736` `restore()`、
   `internal/gateway/redact.go:92` fail-closed、`internal/maskrec/summary.go:122` 缺还原成功率字段。
   **为什么好**：评委追问「magpie 到底怎么做的」时可以当场翻到具体行；
   也顺带定位了 magpie 的两个缺口（无还原成功率、无泄漏断言）—— 这正是 moni 的增量点。

3. **保形替身与五级容错还原（合并版 §4 / §6.1）**
   A 指出中文模型会改写占位符（少一侧花括号、改大小写、自造码），必须多级容错；
   magpie 自己的 `canonical()` / `braces()` 就是为此存在。
   **为什么好**：这是「还原成功率」能不能站稳的唯一前提，也是最容易被现场演示打脸的地方。

### 2.2 来自方案 B（codex）的两处增量

1. **三项 magpie 没有的可证伪指标（合并版 §7.1 / §7.2 / §7.3）**
   - 出站泄漏断言 `leak_scan_hits`：**恒为 0**，扫描对象是「真正发出的 argv payload」；
   - 写库前残留断言：不允许占位符污染 `articles.summary` / `llm_jobs.result` / `reader_messages.content`；
   - 还原成功率 + 去重实体数口径（去重**不能**把每行 `masked_distinct` 相加，否则同一机构被虚增 10 倍）。
   **为什么好**：magpie 的 `maskrec.Summary()` 里根本没有还原成功率与泄漏命中这两个字段。
   「泄漏断言恒为 0 且可用 SQL 复算」是 moni 相对 magpie **可现场证伪**的两格，也是决赛最有说服力的一句。

2. **失败语义默认 fail-open（合并版 §10）**
   脱敏器异常不阻断分析任务（走零依赖极简擦除器放行），严格模式作为开关。
   **为什么好**：magpie 是密码管理器语义（fail-closed），moni 是分析系统 —— 分析不能因为保护层 bug 停摆。
   这条直接服务于用户红线「不能让调用大模型输出的功能失效」。

### 2.3 合并版独有的两处（两版都没有）

1. **任务感知策略矩阵（合并版 §9）**
   联网核查保留公开机构名（否则公网搜不到）、生图换中文泛称（否则编码被烤进像素）、分享成品走 standard。
   **为什么好**：这两条是「脱敏会不会让功能变傻」的真实反例，先在设计阶段解决。

2. **M1 契约与开发/架构分工边界（合并版 §14）**
   冻结 `moni/llm/desensitize/__init__.py` 的对外接口，让架构设计（agy-Carbon）与开发（agy-Hydrogen）
   能在不互相等待的前提下并行；开发期发现越界即判定违约。

### 2.4 被砍掉的（两版都有、合并版没留）

| 项 | 理由 |
|---|---|
| 保形替身（形状替身值） | M0 不做；占位符已足够完成盲态推理 |
| 语义等价替身（L2 拟真假名） | 延后；只有在还原率被现场打脸时才需要 |
| 本地 NER 模型（AstrLink ONNX 39MB） | 零新依赖原则；先靠规则 + 垂类语义 |
| 映射落盘（`keep_map`） | 默认关；原值本就在 `articles` 表里，落盘不带来收益反增资产 |
| UI 开关面板 / 脱敏实验室 | 本轮无 UI；M2 再做 |
| bank bot 通道 | `scripts/bank_bot/run_bot.py` 只读公开栏目，不读私有正文 |

## 3. 实施期与设计稿的偏离（一处，已在合并版 §16 记录）

M1 契约里的「跨进程加密槽」被**整体取消** —— `moni/share/worker_llm.py` 改为**同进程闭环**
（`prepare_outbound` / `finalize_inbound` 在同一进程持有 vault）。
**理由**：跨进程传原值会让原值落到子进程 argv，与脱敏的目的自相矛盾。

---

## 4. 一句话结论

**A 版强在「把 magpie 和 moni 的事实核到底，否决理由与源码索引齐全」；B 版强在「给出 magpie 没有的
两项可证伪指标与正确的失败语义」。合并版的价值在于把两者接在同一根骨头上：
A 保证「覆盖面与还原可靠性」，B 保证「可证伪与不阻断」—— 决赛汇报的差异化正好落在这两格。**
