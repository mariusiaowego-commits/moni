# moni v1.0.56 — Chrome Profile 隔离与数据迁移实施方案

## 1. 背景与根因

在以往版本中，moni 将 macOS 下 Chrome 的用户数据根目录 `~/Library/Application Support/Google/Chrome/` 内的目录当成 `--user-data-dir` 使用：
- `Chrome/Profile 6/`（用户真实 Chrome 账号 profile，UI 对应 `hermes`，含书签、历史记录和 338 个 Cookies）被当作 xwatch 的 `--user-data-dir`，Chrome 自动在其内部创建了 `Default/` 污染层（存放 xwatch 的 274 个 Cookies，其中含 17 个 x.com 登录态 cookies，以及 1.2G Service Worker 缓存）。
- `Chrome/Profile 7/` 被当作 chrome_daemon（36kr 抓取）的 `--user-data-dir`。

后果：
1. 退出状态为 `Crashed` 时，用户日常使用 Chrome 会频繁看到“恢复页面”弹窗，造成“浏览器被反复重启”的体感干扰。
2. 污染用户日常浏览器 profile 根目录，导致 Chrome 单实例锁（Singleton*）冲突。
3. 用户难以分清 Chrome UI 名字（如 `hermes`）与磁盘目录名（`Profile 6`）。

## 2. 核心架构与目标状态

将 moni 的 profile 彻底隔离迁移至独立的用户主目录子路径 `~/.moni/chrome/`：

```
~/.moni/chrome/
├── xwatch/
│   ├── Default/         ← 包含 Cookies (274 个，含 17 个 x.com 登录态)、IndexedDB、Preferences 等
│   └── Local State      ← xwatch 专属 Local State
├── daemon/              ← 原 Profile 7 整体迁移至此
│   ├── Default/
│   └── Local State
└── profile-map.json     ← catalog 目录索引，记录 moni profile 映射与元数据
```

迁移后，Chrome 根目录下的 `Profile 7` 整体消失，`Profile 6/Default`（moni 污染层）消失，而 `Profile 6` 根层的用户真实数据（hermes 账号、338 个 Cookies、书签、历史记录）**完全不受触碰、一个字节不动**。

## 3. 实现组件

1. **统一路径解析 (`moni/fetch/profile_paths.py`)**:
   - `resolve_user_data_dir()` / `resolve_daemon_user_data_dir()` / `resolve_xwatch_user_data_dir()`
   - 环境变量优先 (`MONI_CHROME_USER_DATA_DIR` / `MONI_XWATCH_CHROME_USER_DATA`)。
   - 默认优先使用新路径 `~/.moni/chrome/...`。
   - 兼容旧部署：若新目录未就绪但老目录有数据，自动认领老目录并记录 warning，提示运行迁移脚本。
2. **迁移管理脚本 (`scripts/migrate-chrome-profiles.py`)**:
   - 支持 `--dry-run`（只读检测与计划生成）、`--apply`（带备份与原子移动的实际迁移）、`--rollback`（安全原路回滚）。
   - 备份机制：在 `~/Documents/moni-chrome-profile-backup-YYYYMMDD/` 下创建精简 tar 备份（排除 1.2G 的 `Service Worker` 缓存，仅备份状态文件）。
   - 进程排他检查：使用 `lsof +D` 严格检测占用，防止并发损坏。
   - Cookies 校验：自动通过 SQLite 校验迁移前后总数与 x.com 登录态数量。
3. **Profile 对应关系查看脚本 (`scripts/chrome-profiles.py`)**:
   - 读取 Chrome `Local State` 的 `profile.info_cache` 与磁盘目录，输出对齐表格（UI 名字、磁盘目录、所有者、大小、账号、moni 在用状态）。

## 4. 后续接入点（TODO 接线）

当并行 PR（Chrome 守护护栏 PR #154）合并后，只需在 `moni/fetch/chrome_daemon.py` 和 `moni/fetch/xwatch_following.py` 中将默认路径函数收敛至：
```python
from moni.fetch.profile_paths import (
    resolve_daemon_user_data_dir,
    resolve_xwatch_user_data_dir,
)
```
并在实际生产执行 `scripts/migrate-chrome-profiles.py --apply`。
